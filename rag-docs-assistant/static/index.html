RAG Docs Assistant

A retrieval-augmented Q&A system that answers questions using FastAPI's real documentation — built from scratch, evaluated, and deployed live.

View on GitHub

Why I built this

RAG is one of the most in-demand applied AI skills right now, and most portfolio RAG projects stop at retrieving text and calling an LLM. This one goes further — it includes a real evaluation harness with real numbers, honestly documented limitations, and a full containerized deployment instead of something that only runs locally.

How it works

Ingestion runs once — FastAPI's real docs (155 markdown files) get split into ~1,900 overlapping chunks, embedded locally, and stored in a Chroma vector database tagged by source and type. Every query then retrieves the top-3 most relevant chunks, filtered to exclude changelog noise, and Claude generates an answer grounded only in that retrieved context, citing its source — or says it doesn't know if the docs don't cover it.

Evaluation

Retrieval accuracy11/14 (79%)
Generation accuracy17/18 (94%)

Tested against an 18-question hand-written eval set, including 4 deliberately out-of-scope questions. All 4 were correctly refused, with zero hallucination.

Highlights

  • Built a full RAG pipeline with chunking, embeddings, and grounded generation.
  • Built and ran a real evaluation harness rather than eyeballing results.
  • Found and fixed a real retrieval bug where an oversized changelog file was crowding out relevant docs.
  • Fully containerized and deployed with rate limiting to control API costs.
